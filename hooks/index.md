# Hooks & Filters

FluentPlayer exposes WordPress **actions** and **filters** under the `fluent_player/` prefix so you can extend it without editing plugin files. The free build ships **15 actions** and **77 filters**; FluentPlayer Pro adds **8 more actions** and **12 more filters** of its own — **112 distinct hook names** in total. See the [Full Reference](/hooks/reference) for the complete, source-verified table, including which edition dispatches each hook.

::: warning Version stability — but not all hooks are equally volatile
Hook names and signatures can change between releases. Test on staging and pin to the plugin version you verified against. Signatures on this site are cited with a `file:line` so you can confirm against your installed version.

**26 of the free plugin's hooks are consumed by FluentPlayer Pro**, which makes them a de-facto public API — they are the least likely to change under you. See the [Free → Pro hook contract](/extending/free-pro-contract) for the list and what stability actually guarantees.
:::

## Discover every hook in your version

FluentPlayer dispatches hooks through four forms, not two: the WordPress functions *and* the WPFluent wrappers `$app->doAction()` / `$app->applyFilters()`. It also boots from `boot/`, not just `app/`. A `do_action`/`apply_filters`-only grep over `app/` structurally cannot find `fluent_player/loaded` (dispatched from `boot/app.php`) or `fluent_player/admin_vars` (dispatched via `applyFilters()`) — use this instead:

```bash
P=wp-content/plugins/fluent-player
grep -rnE "(do_action|doAction)\(\s*['\"]fluent_player/"        "$P/app" "$P/boot" | sort
grep -rnE "(apply_filters|applyFilters)\(\s*['\"]fluent_player/" "$P/app" "$P/boot" | sort
```

Repeat both lines against `wp-content/plugins/fluent-player-pro` for the Pro hooks. Four caveats remain, because no single-line regex can cover them:

- `fluent_player/settings_section/{$section}` shows up with its variable un-interpolated — it is a dynamic hook, and you register the *resolved* name.
- `fluent_player/daily_cleanup` is a WP-Cron hook with no literal dispatch site at all, so it never appears.
- `fluent_player/media_milestone` and `fluent_player/layer_event` are dispatched through a variable — `do_action($this->eventName(), $ctx)` at `app/Hooks/Handlers/AbstractBehaviorHandler.php:156` — so the literal names live only in two class constants (`app/Integrations/FluentCrm/BehaviorRegistry.php:17-18`). See [Actions](/hooks/actions#fluent-player-media-milestone).
- A handful of dispatches put the hook name on the line *after* the call — `fluent_player/base_url` (`app/Hooks/Handlers/AdminMenuHandler.php:253-254`) is the clearest example.

All four are covered in the [Full Reference](/hooks/reference), which is generated by a parser rather than a grep.

## How to read an entry

Each hook entry lists its **type** (action or filter), the **source** `file:line`, a **table of arguments**, and one **runnable example** with the correct priority and accepted-argument count. For filters, always `return` the (possibly modified) first argument.
